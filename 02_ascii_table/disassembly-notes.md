# C 程序的真实 16 位反汇编说明

本说明对应 `src/ascii.c`，编译选项为 `wcc -0 -ms -od -d2`。`results/ascii_c.disasm.txt` 是 `wdis` 对实际 `.build/ascii_c.obj` 的带机器码清单，`results/ascii_c.generated.asm` 是同一目标文件经 `wdis -a` 得到的汇编文本。导出文件保留运行代码与常量，省略 DWARF 调试元数据及主机路径；`results/ascii_c.annotated.asm` 对相同指令追加中文分号注释。

以下地址均为目标文件 `_TEXT` 段的相对偏移，不是 EXE 装入 DOS 后的运行地址。清单中的外部 `CALL` 机器码暂为 `E8 00 00`，其目标由目标文件重定位记录和链接器确定，不能据此认为它调用下一条指令。原始清单末尾记录 `No disassembly errors`，主函数代码长度为 `82h = 130` 字节。

## 函数与栈帧

`main_` 是 C 函数 `main(void)` 的符号。它由 C 运行库启动代码调用；启动代码负责程序环境、数据段初始化和退出处理。手写汇编中的 `main` 则被指定为 EXE 入口，自己初始化 DS，并以 `INT 21h / 4Ch` 结束。C 函数只需把返回值放入 AX，再 `RET` 返回给启动代码。

实际函数入口如下：

```asm
mov  ax,1aH
call near ptr __STK
push bx
push cx
push dx
push si
push di
push bp
mov  bp,sp
sub  sp,8
```

`__STK` 是运行库提供的栈检查过程，AX 中的 `1Ah` 是此处生成的检查需求值。编译器保存 BX、CX、DX、SI、DI、BP，以 BP 建立栈帧，再分配 8 字节局部空间。这里的 `int` 为 16 位，各槽占 2 字节：

| 栈位置 | 对应数据 | 真实清单中的证据 |
| --- | --- | --- |
| `[BP-2]` | `letter` | `0012: MOV WORD PTR -2[BP],61H` 初始化为 `'a'` |
| `[BP-4]` | `column` | `0028: MOV WORD PTR -4[BP],0` 初始化列号 |
| `[BP-6]` | `row` | `0017: MOV WORD PTR -6[BP],0` 初始化行号 |
| `[BP-8]` | 编译器的返回值暂存槽 | `0071` 写入 0，`0076` 再取入 AX |

`[BP]` 保存旧 BP，`[BP+2]～[BP+10]` 为其余保存的寄存器，`[BP+12]` 是调用 `main_` 时的近返回地址。函数末尾先 `MOV SP,BP` 释放局部空间，再按相反顺序 POP 各寄存器，最后 `RET`。AX 留作返回值，不在这组保存和恢复中。

## C 循环如何变成比较与跳转

| C 语句 | 真实地址及标签 | 编译后的控制流 |
| --- | --- | --- |
| `letter = 'a'` | `0012`，`L$1` | 把 `61h` 写入 `[BP-2]` |
| `row = 0` | `0017` | 把 0 写入 `[BP-6]` |
| `row < 2` | `001F～0025`，`L$2` | `CMP [BP-6],2`，`JL L$3` 进入行体，否则跳到结束 |
| `column = 0` | `0028`，`L$3` | 每行都重新初始化 `[BP-4]` |
| `column < 13` | `002D～0033`，`L$4` | 比较列号与 `0Dh`；不足 13 则输出字母，否则转去换行 |
| `printf("%c", letter)` | `0036～0041`，`L$5` | 压入 letter 和格式串地址，调用 `printf_`，清理 4 字节参数 |
| `++letter` | `0044` | `INC WORD PTR -2[BP]` |
| `column < 12` | `0047～0050` | 比较列号与 `0Ch`；最后一列跳过输出空格的分支 |
| `printf(" ")` | `0053～005A`，`L$7` | 只在 column 为 0～11 时输出空格 |
| `++column` | `005D～0060`，`L$8` | 增加列号并跳回 `L$4` |
| `printf("\n")` | `0062～0069`，`L$9` | 完成本行后输出换行 |
| `++row` | `006C～006F`，`L$10` | 增加行号并跳回 `L$2` |
| `return 0` | `0071～0081`，`L$11/L$12` | AX 取 0，释放栈帧，恢复寄存器，返回 |

计数范围是 `row = 0,1`、`column = 0～12`，因此恰好输出 2×13 个字母。这里使用 `JL/JGE`，因为源代码的循环变量是有符号 `int`。关闭优化后，某些路径先经过中转标签再 `JMP`；注释版保留这些原始指令，没有按手写习惯改写它们。

C 的 `for` 并不要求编译器生成 8086 的 `LOOP` 指令。此编译结果将变量放在栈中，用 `CMP/JL/JGE/JMP` 维护循环；`src/ascloop.asm` 则使用 `LOOP` 实现双重循环。

## printf 的参数与字符串

字母输出对应的实际指令为：

```asm
mov  ax,word ptr -2[bp]       ; letter
push ax
mov  ax,offset DGROUP:L$14   ; "%c"
push ax
call near ptr printf_
add  sp,4
```

`printf` 是可变参数函数，此处按 C 的栈传参方式，将实参从右向左压栈：先压入 16 位 letter，再压入格式串的近地址。`CALL` 还自动压入 2 字节近返回地址，所以在 `printf_` 刚进入、尚未建立自己的栈帧时，`[SS:SP]` 是返回地址，`[SS:SP+2]` 是格式串地址，`[SS:SP+4]` 是 letter。返回后调用者用 `ADD SP,4` 释放两个实参。

输出空格和换行时只有一个格式串参数，因此相应位置使用 `ADD SP,2`。small 模型的代码和数据均使用近地址，字符串位于 DGROUP，传入其 16 位偏移即可。不能从这个可变参数函数的调用方式，推断 Open Watcom 所有普通函数也都只用栈传参。

| 常量地址 | 实际字节 | C 含义 |
| --- | --- | --- |
| `CONST:0000`，`L$14` | `25 63 00` | `"%c"` |
| `CONST:0003`，`L$15` | `20 00` | `" "` |
| `CONST:0005`，`L$16` | `0A 00` | `"\n"` |

C 字符串以 NUL（`00h`）结尾。手写汇编的 DOS `AH=09h` 字符串则以 `$`（`24h`）结尾，两者规则不同。C 常量中只存 LF，DOS C 运行库在文本输出时把它转换为 CR/LF；汇编版直接输出 CR/LF 两个字节。

## 如何理解反汇编器的指示

`wdis -a` 在开头固定输出 `.387/.386p` 汇编器指示，它们不是主函数执行的 386 指令。实际 `_TEXT` 段标记为 `USE16`，其中上述 MOV、PUSH、CMP、跳转、CALL 和 RET 均为 8086 可用指令。CPU 目标由实际编译参数 `-0` 指定。

`-d2` 还在目标文件中产生 `.debug_info`、`.debug_line` 等 DWARF 段，保存类型、源路径、变量名和行号。这些元数据可能被工具显示为 `USE32` 段，其 DB/DW/DD 数据不作为处理器指令执行。反汇编清单省略这些段，避免把元数据和运行代码混淆；所有运行指令与常量保持实际反汇编结果。逐行中文注释中的偏移可对照带机器码清单核验。
